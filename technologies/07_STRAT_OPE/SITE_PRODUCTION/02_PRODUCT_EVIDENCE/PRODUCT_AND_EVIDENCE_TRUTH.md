## 1. Product system
The corpus defines a controlled ladder, not four interchangeable offers:
qualification → paid Diagnostics → Session → Sprint 30-60-90 → Support.
Each transition is conditional. A prior product can legitimately end the route.

### Qualification (pre-product filter)
Purpose: decide whether Diagnostics may be offered without solving the problem for free.
Current scale: six criteria × 0–3; 15–18 admit, 12–14 admit with conditions, 7–11 Hold, 0–6 Stop.
Output: qualification verdict + Diagnostics conditions + commercial decision.
Source: Qualification Protocol v1.0.

### Product 1 — Diagnostics
Role: mandatory paid entry into the technology.
Job: verify the management problem and current strategy→operations→result contour; convert complaint to evidenced Problem Unit; establish transition conditions.
Outputs: Problem Unit map, confirmed facts, contour-gap map, transition/refusal conditions, constraints of next step.
Current verdicts: Go / Conditional Go / Hold / Stop.
Commercial v1.0 format: standard 7–10 working days, RUB 650k–1.2m; expanded 10–15 working days, RUB 1.2m–2.0m.
Evidence boundary: price/duration are current commercial package facts, not technology invariants; they may change without reopening T1.
Sources: OS v1.0; Evidence Matrix; Commercial Proposal Diagnostics v1.0; Commercial Package v1.0.

### Product 2 — Session
Entry: confirmed diagnosis and allowed transition.
Job: narrow the choice; select strategic working set, operational set and construct Bridge.
Required outputs: selected working sets, owners, metrics, Bridge map, Sprint charter.
Boundary: not brainstorming; not an automatic consequence of Diagnostics; not a catalog demonstration.
Source: OS v1.0; Session client v0.3; Error Scenarios v1.0.

### Product 3 — Sprint 30-60-90
Entry: ready Bridge + Sprint charter + owners/metrics/baseline.
Job: test the assembled contour in execution.
Launch constraint: no more than 3–5 instruments.
Outputs: baseline, decision log, 30/60/90 control, evidence of result/instability, Sprint verdict.
Boundary: no guaranteed financial result; no Sprint before Session/Bridge; no result claim without baseline.
Source: OS v1.0; Sprint client v0.3; Error Scenarios v1.0.

### Product 4 — Support
Entry: active post-Sprint contour with a real object and rollback/drift risk.
Job: maintain/check stability, detect drift, decide continue/rebuild/new Sprint/exit.
Boundary: cannot be sold merely to continue consultant occupancy.
Source: OS v1.0; Support client v0.3; Error Scenarios v1.0.

## 2. Evidence architecture
Evidence chain:
management conclusion → fact → source → artifact → verification owner → score/impact → stop-line.
A document/process/metric/owner existing on paper is not evidence that the contour works.
A stage is complete only when its required artifact is ready and the transition gate is satisfied; elapsed time is insufficient.
Sources: Evidence Matrix v1.0; Artifact & Transition Register v1.0.

- automatic Sprint after Session;

- direct book-level provenance while source books remain non-READ.

## 5. Product transition matrix
| From | Required object | Required evidence/artifact | Allowed next | Stop/Hold condition |
|---|---|---|---|---|
| Qualification | management pain + decision-maker | mandate/data/readiness | Diagnostics | no mandate/data/paid-diagnostic readiness |
| Diagnostics | verified Problem Unit | facts + contour + triggers + verdict | Session / conditional Session | Hold/Stop |
| Session | confirmed diagnosis | working sets + Bridge + owners/metrics + Sprint charter | Sprint | return Diagnostics / Hold / Stop |

| Support | active post-Sprint contour | active-contour passport + drift evidence | continue / new Sprint / rebuild / exit | no active object |
