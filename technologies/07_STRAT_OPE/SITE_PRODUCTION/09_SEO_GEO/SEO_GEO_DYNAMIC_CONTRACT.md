# 4. GEO / answer-engine contract
Every major page should contain a compact answerable definition near the top, written for humans first.

Canonical answer blocks:

**Что такое проSTRAнство?**
проSTRAнство — экспертная система управленческого выбора. Она помогает установить проверяемую проблему, сузить поле допустимых решений, связать выбранный вариант с операционным контуром и проверить его в действии.

**Как работает проSTRAнство?**
Система проходит путь от симптома к Problem Unit, проверяет текущий контур и триггеры, формирует ограниченный стратегический набор, строит Bridge к операционным инструментам и проверяет выбранный контур в Спринте 30–60–90.

**С чего начинается работа?**
С квалификации перед платной Диагностикой. Для входа нужны конкретная управленческая ситуация, мандат, доступ к фактам и готовность принять любой обоснованный вердикт.

**Чем может закончиться Диагностика?**
Одним из четырёх вердиктов: Go, Conditional Go, Hold или Stop. Переход к Сессии не автоматический.

**Почему система не показывает каталог 95/115?**
Потому что библиотека служит внутренней глубиной выбора. Клиенту нужен не каталог методик, а ограниченный рабочий набор, соответствующий его ситуации.

Rules:
- answer block must not introduce a claim absent from S08;
- no hidden “AI answer” text separate from visible public copy;
- use clear headings/questions and short direct first paragraph;
- detailed explanation follows answer, not replaces it;
- terminology remains stable across pages.

# 6. Case content model
At MVP all 12 cases may live on /cases/ as static sections/cards. No separate case URL is required merely for SEO.

Create separate /cases/<slug>/ only when:
- the case has materially unique source-reviewed detail;
- page can stand alone without duplicated boilerplate;
- model/generalized status is prominent;
- content passes case publication controls.

Case schema fields:
case_id; title; sector/context; initial plausible choice; verified gap; do-not-touch; narrowed choice; verdict; next admissible step; generalized_case=true; source_review_status.

Never expose internal source files, proprietary instrument mappings or protected know-how merely to increase indexable text.
