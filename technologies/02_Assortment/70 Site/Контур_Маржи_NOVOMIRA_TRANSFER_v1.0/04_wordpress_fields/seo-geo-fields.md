# Контур Маржи — SEO/GEO поля для WordPress

Источник фактов: `<head>` в `01_source/standalone-src.dc.html` (идентичен `<head>` финального `Контур Маржи - сайт технологии (standalone).html`, сверено построчно). Все title/description/JSON-LD ниже — дословные цитаты из исходника, кроме WebSite и BreadcrumbList — их в источнике нет, они предложены как черновик (помечено явно) и требуют утверждения автором.

## 1. Домен: открытый вопрос до начала работы с полями

Текущий `<head>` жёстко ссылается на `https://c-level-insight.ru/kontur-marzhi/` (canonical, og:url, og:image, JSON-LD `@id`). По вводным задачи фактический препрод-домен — `opesys.7vctr.ru`, а `c-level-insight.ru` — предполагаемый будущий боевой домен площадки C-Level Insight. Ни один из этих доменов не подтверждён в этой задаче как окончательный production-адрес страницы `/kontur-marzhi/`.

**Решение принято заранее (backlog v1.1/v1.2, не блокер):** переносим поля as-is с `c-level-insight.ru` как рабочим placeholder-доменом (это и есть текущее «принятое» значение в исходнике), и фиксируем ниже точный список мест для будущей замены.

### Места будущей замены домена

| Поле | Текущее значение | Где физически менять в WP |
|---|---|---|
| `canonical` | `https://c-level-insight.ru/kontur-marzhi/` | SEO-плагин → поле Canonical URL страницы |
| `og:url` | `https://c-level-insight.ru/kontur-marzhi/` | SEO-плагин → Social/OpenGraph → URL (обычно подтягивается из canonical автоматически) |
| `og:image` | `https://c-level-insight.ru/kontur-marzhi/og-kontur-marzhi.jpg` | SEO-плагин → Social image (после загрузки файла, см. `wordpress-assets-map.md`, п.5) |
| JSON-LD `Organization.@id` / `.url` | `https://c-level-insight.ru/#org` / `https://c-level-insight.ru/` | Если schema генерирует SEO-плагин — настройки компании/бренда плагина. Если JSON-LD вставляется вручную — прямая правка блока |
| JSON-LD `WebPage.@id` | `https://c-level-insight.ru/kontur-marzhi/` | Как правило берётся автоматически из permalink страницы |
| JSON-LD `Service.provider.@id` | `https://c-level-insight.ru/#org` | Связано с Organization выше |
| Footer: 6 ссылок на другие технологии | `https://c-level-insight.ru/technologies/` | См. `content-links-map.md`, п.4 — там же открытый вопрос про то, что все шесть ведут на один и тот же placeholder-URL |

## 2. Title / Description / Robots

| Поле | Значение (дословно из источника) |
|---|---|
| `<title>` | Контур Маржи — технология управления маржей ассортимента в омниканальных продажах \| C-Level Insight |
| `meta description` | Контур Маржи показывает, где товарная позиция в канале теряет управляемую прибыль, и закрепляет за красной зоной владельца, решение, срок и метрику проверки. Вход — платная Диагностика. |
| `meta robots` | `index, follow` |
| `lang` (`<html lang="…">`) | `ru` |

Длина title — 111 символов (с учётом « | C-Level Insight»), длина description — 199 символов. Оба превышают типичные рекомендации Google по отображаемой длине (обычно ~60 и ~155–160 символов) — это уже существующее решение из принятой версии (Акт приёмки не отмечал это как проблему), переносится как есть; сокращение — не входит в задачу переноса (было бы правкой текста, что запрещено правилами проекта).

Обратите внимание: `og:title`/`og:description` отличаются от `<title>`/meta description — это осознанное разделение (SEO-заголовок длиннее и содержит бренд-хвост, OG-заголовок короче для соцсетей). Сохранить оба варианта отдельно, не схлопывать в один при переносе в SEO-плагин.

## 4. Twitter Card

| Поле | Значение |
|---|---|
| `twitter:card` | `summary_large_image` |

**ТРЕБУЕТ УТОЧНЕНИЯ:** в источнике не заданы отдельные `twitter:title`, `twitter:description`, `twitter:image` — большинство SEO-плагинов (Yoast, Rank Math) в этом случае используют fallback на `og:title`/`og:description`/`og:image`. Решить при настройке: оставить fallback (проще, соответствует источнику как есть) или явно продублировать поля под Twitter — это расширение, не перенос, поэтому по умолчанию рекомендуется fallback.

## 5. JSON-LD — из источника (переносится дословно)

Источник — единый `<script type="application/ld+json">` с `@graph` из 4 сущностей. Ниже — точная копия структуры (значения не менялись, только отформатировано для читаемости).

### 5.1 Organization

```json
{
  "@type": "Organization",
  "@id": "https://c-level-insight.ru/#org",
  "name": "C-Level Insight",
  "url": "https://c-level-insight.ru/",
  "description": "Платформа управленческих технологий для C-level: семь технологий, включая Контур Маржи."
}
```

### 5.2 WebPage

```json
{
  "@type": "WebPage",
  "@id": "https://c-level-insight.ru/kontur-marzhi/",
  "name": "Контур Маржи — технология управления маржей ассортимента",
  "isPartOf": { "@id": "https://c-level-insight.ru/#org" },
  "inLanguage": "ru-RU",
  "about": "Управляемая маржа ассортимента в омниканальных продажах"
}
```

Технически `isPartOf` в источнике указывает на `Organization`, а не на `WebSite` — обычно `WebPage.isPartOf` ссылается на `WebSite`. Так как `WebSite`-сущности в источнике нет (см. §5.6), это расхождение унаследовано из принятой версии; при добавлении `WebSite` в WordPress имеет смысл переключить `isPartOf` на новый `WebSite.@id` — это улучшение схемы, требует решения автора, не делается автоматически в рамках «переноса как есть».

### 5.3 Service + OfferCatalog

```json
{
  "@type": "Service",
  "name": "Контур Маржи",
  "provider": { "@id": "https://c-level-insight.ru/#org" },
  "serviceType": "Технология управления ассортиментной прибылью",
  "areaServed": "RU",
  "hasOfferCatalog": {
    "@type": "OfferCatalog",
    "name": "Продуктовая линейка",
    "itemListElement": [
      { "@type": "Offer", "name": "Диагностика", "description": "Первый платный вход: карта потерь, красные зоны, метрики проверки, контрольный вердикт." },
      { "@type": "Offer", "name": "Сессия", "description": "Красная зона превращается в решение: коридор цены, условие промо, правило по запасу." },
      { "@type": "Offer", "name": "Спринт 30-60-90", "description": "Проверка решения на ассортиментном контуре." },
      { "@type": "Offer", "name": "Сопровождение", "description": "Контур работает в ритме компании без внешнего участия." }
    ]
  }
}
```

Порядок офферов — Диагностика → Сессия → Спринт 30-60-90 → Сопровождение — совпадает с продуктовой логикой (жёсткое правило проекта), менять нельзя.

### 5.4 FAQPage

```json
{
  "@type": "FAQPage",
  "mainEntity": [
    { "@type": "Question", "name": "Чем это отличается от BI-панели, которая у нас уже есть?", "acceptedAnswer": { "@type": "Answer", "text": "Панель показывает состояние. Контур Маржи назначает владельца, решение, срок и метрику проверки по строке SKU × канал, и не требует новой системы." } },
    { "@type": "Question", "name": "Почему Диагностика платная?", "acceptedAnswer": { "@type": "Answer", "text": "Диагностика — работа с данными компании и первая карта потерь. Результат остаётся у компании независимо от продолжения работы." } },
    { "@type": "Question", "name": "Какие данные нужны на входе?", "acceptedAnswer": { "@type": "Answer", "text": "Продажи по позициям и каналам, цена и промо, комиссии каналов, логистика, возвраты и запас." } },
    { "@type": "Question", "name": "Кто участвует со стороны компании?", "acceptedAnswer": { "@type": "Answer", "text": "Роли с мандатом: коммерция, категорийное управление, финансы, операции." } },
    { "@type": "Question", "name": "Что если после Диагностики продолжать не нужно?", "acceptedAnswer": { "@type": "Answer", "text": "Право на STOP сохраняется у обеих сторон. Вердикт No Fit означает, что технология сейчас не уместна." } },
    { "@type": "Question", "name": "Технология остаётся у команды или требует сопровождения?", "acceptedAnswer": { "@type": "Answer", "text": "Контур проектируется так, чтобы работать без внешнего участия. Сопровождение — ритм проверки, а не условие работоспособности." } }
  ]
}
```

**Важно:** текст вопросов/ответов здесь текстуально идентичен видимому блоку FAQ на странице (секция 16 в `elementor-transfer-map.md`). При переносе в Elementor Accordion эти два места (видимый контент и JSON-LD) должны совпадать дословно — иначе будет расхождение видимого/структурированного контента, что нарушает п.11 gate-листа Акта приёмки («JSON-LD валиден и не продублирован») и общие рекомендации Google по FAQ-разметке.

### 5.5 Если SEO-плагин сам генерирует schema

Если WordPress SEO-плагин (Yoast/Rank Math) генерирует собственную `Organization`/`WebPage`/`FAQPage` schema автоматически — **не дублировать** источники JSON-LD (правило из `Инструкция_…v1.0.md`, раздел 7: «должен быть один согласованный источник schema»). В этом случае описанный выше JSON-LD используется как содержательный эталон (какие поля и в каких формулировках должны попасть в итоговую schema), а не как код для вставки один-в-один поверх плагинной генерации.

## 6. Schema, которых в источнике нет — черновик (ТРЕБУЕТ ПОДТВЕРЖДЕНИЯ АВТОРА)

Ниже — предложенные черновики по прямому требованию промпта. Факты о компании не выдуманы: используются только значения, уже присутствующие в источнике (`Organization.name`, `Organization.url`, `og:site_name`). Где данных не хватает — оставлен явный плейсхолдер.

### 6.1 WebSite (черновик)

```json
{
  "@type": "WebSite",
  "@id": "https://c-level-insight.ru/#website",
  "name": "C-Level Insight",
  "url": "https://c-level-insight.ru/",
  "inLanguage": "ru-RU",
  "publisher": { "@id": "https://c-level-insight.ru/#org" }
}
```

`potentialAction` (SearchAction) намеренно не добавлен — в источнике нет данных о наличии поиска по сайту C-Level Insight; добавлять его без подтверждения означало бы выдумывать несуществующую функциональность.

### 6.2 BreadcrumbList (черновик)

```json
{
  "@type": "BreadcrumbList",
  "itemListElement": [
    { "@type": "ListItem", "position": 1, "name": "Главная", "item": "https://c-level-insight.ru/" },
    { "@type": "ListItem", "position": 2, "name": "Технологии", "item": "https://c-level-insight.ru/technologies/" },
    { "@type": "ListItem", "position": 3, "name": "Контур Маржи", "item": "https://c-level-insight.ru/kontur-marzhi/" }
  ]
}
```

Промежуточный уровень «Технологии» взят из фактически существующей в разметке ссылки (все 6 пилюль футера ведут на `https://c-level-insight.ru/technologies/`, см. `content-links-map.md` п.4) — не выдуман, но сама страница `/technologies/` не проверялась на существование в рамках этой задачи (offline-подготовка, без сетевых обращений).

## 7. H-структура (уже соответствует требованиям)

Один `<h1>` — в Hero («Прибыль уходит тихо и всегда в одном месте»). `<h2>` — на каждой из 19 секций, где есть заголовок (не на всех 19 есть h2 — служебные секции «Лента разделов» и лайтбокс-модал заголовка не имеют). `<h3>` — на карточках продуктов (4 шт. в секции 11) и заголовках карточек кейсов/материалов. Проверено по атрибутам `data-t-h2`/`data-t-h3` в разметке — соответствует Gate-пункту 2 из Акта приёмки.
