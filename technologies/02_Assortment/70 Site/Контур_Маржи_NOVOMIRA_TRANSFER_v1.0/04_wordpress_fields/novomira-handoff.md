# Контур Маржи — краткое ТЗ для Novomira

Статус этого документа: техническая передача-инструкция, которая идёт вместе с пакетом `Контур_Маржи_NOVOMIRA_TRANSFER_v1.0` в Novomira. Сама передача, подключение Novomira к wp-admin и публикация в этой задаче не выполнялись — это только подготовка пакета документов (см. ограничение задачи ниже).

## 1. Ограничение этой задачи

Этот документ и весь пакет `04_wordpress_fields/` подготовлены оффлайн, без единого обращения к WordPress, Novomira MCP или любым сетевым/публикационным инструментам. Публикация страницы `/kontur-marzhi/` в WordPress — отдельный следующий шаг, требующий отдельного GO после проверки этого пакета (см. `Инструкция_WordPress_Elementor_Claude_Code_Novomira_Контур_Маржи_v1.0.md`, раздел 1B и `README_СОСТАВ_ПАКЕТА_И_ЧЕГО_НЕ_ХВАТАЕТ.md`, раздел 8 «Стоп-линия»).

## 2. Что переносить

1. `01_source/standalone-src.dc.html` и финальный `Контур Маржи - сайт технологии (standalone).html` — как эталон разметки, контента и стилей для извлечения (не как готовый production HTML — оба являются экспортом Claude Design с рантайм-обвязкой, см. §3).
2. `02_assets/vizw/` — 12 WebP-визуализаций, основной показ на странице.
3. `02_assets/viz/` — 12 PNG-визуализаций, резервные оригиналы (не подключены ни к одному элементу в текущей разметке, см. `wordpress-assets-map.md`, §1).
4. `04_wordpress_fields/` — весь этот пакет из 7 документов (карта секций, ассетов, SEO, формы, ссылок, это ТЗ, QA-чек-лист).
5. `03_transfer_docs/` — карта переноса v1.1, рабочая инструкция, описание визуализаций, письмо — контекст для понимания принятых ранее решений.
6. `05_qa/Акт_Приемки_Контур_Маржи_FINAL_CANDIDATE_v1.0.md` — зафиксированные пределы и принятые решения по art direction.

## 3. Что НЕ переносить (служебные файлы и папки)

| Что | Почему |
|---|---|
| `_ds/` (внутри исходного ZIP) | Токены дизайн-системы Claude Design, не нужны в WordPress — стили извлекаются как конкретные значения (цвета, радиусы, шрифты), а не как система токенов |
| `ref/` (внутри ZIP) | Референсные/рабочие файлы сборки |
| `uploads/` (внутри ZIP, 156 файлов) | Содержит ассеты ДРУГОЙ технологии линейки (обнаружено: `CLM`/«Управление Директорами» визуализации) — не относится к Контур Маржи вообще, переносить нельзя ни при каких условиях |
| `x-dc` / `<x-dc>` обвязка в HTML | Служебная разметка шаблонизатора Claude Design, не валидный HTML вне рантайма |
| `<script type="text/x-dc">…</script>` в конце `standalone-src.dc.html` (класс `Component extends DCLogic`) | Рантайм Claude Design — сама логика (reveal-on-scroll, лайтбокс, FAQ-аккордеон, before/after, фильтр материалов, scroll-spy) должна быть переосмыслена под WordPress-стек, см. `elementor-transfer-map.md`, §0. Копировать этот JS-класс в WordPress один в один нельзя, он завязан на `DCLogic`/`this.root()`/`this.props`, которых в WP нет |
| `02_assets/image-slot.js` | Компонент drop-зон рантайма Claude Design (`omelette`-заготовка) — не работает вне него, см. `wordpress-assets-map.md`, §3 |
| `support.js` | Служебный JS сборки |
| `<template id="__bundler_thumbnail">` в `<head>` | Служебный превью-шаблон бандлера, не относится к контенту страницы |
| `{{ }}`-интерполяция (`onClick="{{ openViz }}"` и т.п.) в `.dc.html` | Синтаксис шаблонизатора Claude Design, не браузерный JS — при переносе заменяется реальными обработчиками |
| Любые prompt/negative-prompt тексты image slots (см. карту переноса v1.1, раздел 4) | Рабочие промпты для будущей генерации изображений — служебная информация для дизайнера, не для публичной страницы |

## 4. Где допустим Custom HTML/CSS

Только там, где точность арт-дирекшн важнее редактируемости через UI — подробный список с обоснованием по каждой секции в `elementor-transfer-map.md`:

- 4 тёмные «кинематографические» сцены: Hero (01), Где течёт маржа (06), Красная зона (08), CTA и форма (17) — слоистые CSS-градиенты, `perspective()`, анимированная медная линия;
- общий лайтбокс-модал для 13 точек показа схем (не дублировать на каждую секцию);
- переключатель before/after в секции «Ситуация» (04);
- тёмная карточка кейсового слоя (13) и крупная карточка материалов (14) — та же логика слоистых градиентов, что у сцен.

Текст поверх этих сцен (заголовки, подписи, кнопки) — всё равно должен быть в Elementor-виджетах поверх Custom HTML-фона, не зашит в статичную разметку, иначе потеряется редактируемость контента.

## 5. Где обязательно Elementor-editable

- Все текстовые секции без уникальной анимации (03, 05 текстовая часть, 07, 09, 10, 11, 12, 15, 16) — стандартные контейнеры/виджеты;
- FAQ (16) — нативный Elementor Accordion/FAQ widget, не Custom HTML (см. обоснование в `elementor-transfer-map.md`, секция 16);
- Форма заявки (17) — нативный form-плагин (Elementor Forms / WPForms / Fluent Forms), не статичная разметка — в источнике форма без единого байта логики отправки, собирать заново (см. `form-spec.md`);
- Материалы (14) — рекомендовано перевести на WP posts + Loop Grid вместо статичных карточек, поскольку это единственный блок, который по проектному правилу обязан стать обновляемым блоговым контуром;
- Footer (18) — рекомендовано как глобальный Theme Builder шаблон, переиспользуемый на всех 7 страницах линейки технологий.

## 6. Подключение Novomira

Подключение Novomira к сайту (установка `novamira.zip`, активация плагина, `discover-abilities`, временное включение AI Abilities, вход в wp-admin) — действие самого пользователя на своей WordPress-инсталляции, выполняется вне этой задачи. Процесс подробно описан в `Инструкция_WordPress_Elementor_Claude_Code_Novomira_Контур_Маржи_v1.0.md`, разделы 1A–1B и 3.3 — этот документ не дублирует шаги подключения, а ссылается на уже отработанный в предыдущей сессии процесс.

Принцип безопасности при будущей работе через Novomira (напоминание из инструкции, не решение этой задачи): работать сначала на staging, сделать backup перед стартом, включать AI Abilities только на время работы, не давать задачу «сделай красиво / сам реши», не разрешать массовое удаление файлов или перезапись темы без отдельного разрешения, production-публикация только после QA-gate (`qa-after-transfer.md`).
