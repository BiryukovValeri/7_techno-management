# Контур Маржи — чек-лист QA после переноса в WordPress

Этот чек-лист выполняется ПОСЛЕ фактического переноса страницы `/kontur-marzhi/` в WordPress (не в рамках подготовки этого пакета документов). Источник требований: `Инструкция_WordPress_Elementor_Claude_Code_Novomira_Контур_Маржи_v1.0.md` (разделы 4 и 8), `Перенос_в_WordPress_Novomira_Контур_Маржи_v1.1.md` (раздел 6), `Акт_Приемки_Контур_Маржи_FINAL_CANDIDATE_v1.0.md` (раздел 8, gate для финальной приёмки), и содержательные факты из этого пакета (`elementor-transfer-map.md`, `wordpress-assets-map.md`, `seo-geo-fields.md`, `form-spec.md`, `content-links-map.md`).

## 1. Верстка и адаптивность

- [ ] Desktop 1440 — визуально совпадает с принятым art direction (тёмный cinematic hero, красная вертикаль, медная линия, мягкие радиусы 14–28px, светлые «бумажные» секции)
- [ ] Mobile 430 — без горизонтального скролла
- [ ] Mobile 390 — без горизонтального скролла
- [ ] Mobile 360 — без горизонтального скролла
- [ ] На всех трёх мобильных ширинах: `document.documentElement.scrollWidth === document.documentElement.clientWidth` (и то же для `document.body`)
- [ ] Hero на мобильном — отдельная композиция (не обрезанный десктоп), как в источнике (`data-mob`/`data-desk` переключение слоёв)
- [ ] Лента разделов (секция 02) на мобильном — горизонтальный скролл с видимым затуханием справа, а не обрезанный список
- [ ] Все 12 визуализаций отображаются в WebP, без искажения пропорций (1920×1080 → responsive)
- [ ] Мягкие радиусы 14–28px нигде не превращены в острые углы или в другой радиус

## 2. Структура и драматургия

- [ ] Порядок 19 секций не изменён: Hero → Лента → Что открывает → Ситуация → Ядро технологии → Где течёт маржа → Карта утечки → Красная зона → Владелец красной зоны → Это не → Управляемость → Продуктовая линейка → Визуализации → Кейсы → Материалы → Стоимость и границы → FAQ → CTA и форма → Footer (полный список секций — `elementor-transfer-map.md`)
- [ ] Драматургия «утечка → место → владелец → маршрут → диагностика» читается как единая история, не как редакционная подборка блоков
- [ ] Блок «Материалы» присутствует и связан с реальными WordPress posts (не статичная заглушка)
- [ ] Блок «Это не» присутствует, рамка 2px вокруг таблицы сохранена, не превращён в агрессивное сравнение
- [ ] Продуктовая логика Диагностика → Сессия → Спринт 30-60-90 → Сопровождение — порядок карточек не нарушен, у карточки «Диагностика» сохранена рамка 2px (отличает от остальных трёх)
- [ ] Страница не превращена в BI/dashboard/финансовую панель (нет добавленных таблиц с цифрами, графиков поверх принятого визуального языка)

## 3. Заголовки и доступность

- [ ] Один `<h1>` на странице (в Hero)
- [ ] `<h2>` на каждой секции с заголовком, `<h3>` на карточках продуктов/материалов/кейсов — иерархия не нарушена
- [ ] У всех 12 визуализаций и у всех загруженных image slot изображений — заполнен `alt` (тексты — из `wordpress-assets-map.md`, разделы 2 и 4)
- [ ] `prefers-reduced-motion: reduce` отключает все анимации (проверить с включённой системной настройкой)
- [ ] Все интерактивные элементы (кнопки лайтбокса, FAQ, фильтр материалов, форма) достижимы с клавиатуры, `focus-visible` виден
- [ ] Кнопки/поля формы — минимальная высота тач-таргета ≥ 44px

## 4. CTA и форма

- [ ] Все 8 CTA ведут в рабочие места (полный список — `content-links-map.md`, §1): 2× шапка «Диагностика», основной + вторичный CTA в Hero, «Смотреть карту ↓», CTA в продуктовой линейке, CTA в материалах, кнопка отправки формы
- [ ] Форма реально отправляет заявку (в источнике не было ни одного байта логики отправки — см. `form-spec.md`, §1 — проверить, что в WordPress это исправлено, а не унаследовано как «пустая кнопка»)
- [ ] Все 5 полей формы имеют видимые labels (см. `form-spec.md`, §2)
- [ ] Success message после отправки — присутствует и утверждён автором (в источнике отсутствовал, см. `form-spec.md`, §5)
- [ ] Текст согласия / privacy note — присутствует и утверждён автором/юристом, если решено, что он нужен (в источнике отсутствовал полностью, см. `form-spec.md`, §6)
- [ ] Текст-примечание под кнопкой формы («Диагностика — платный первый шаг…») сохранён дословно
- [ ] CTA «Запросить платную Диагностику» НЕ заменён на формулировку про бесплатный аудит (жёсткое правило проекта)

## 5. SEO / GEO

- [ ] Canonical указывает на актуальный на момент публикации домен (placeholder `c-level-insight.ru` заменён на реальный, если он уже известен — см. `seo-geo-fields.md`, §1)

## 6. Чистота публичного слоя

- [ ] В публичной странице НЕТ текста промптов image slots (положительных/негативных)
- [ ] НЕТ placeholder-текста, browse files, TODO
- [ ] НЕТ служебных атрибутов/классов Claude Design в видимом контенте (`x-dc`, `data-dc-script`, `{{ }}`-интерполяция и т.п. — допустимы только как исходный код, не как видимый текст)
- [ ] `_ds`, `ref`, `uploads` (с ассетами других технологий), bundler-слой — НЕ загружены в WordPress ни в каком виде

## 7. Вес страницы и производительность

- [ ] Вес страницы после оптимизации приемлем для WordPress (12 WebP по ~120–145 КБ на показ — не грузить вместо них PNG по 700+ КБ, см. `wordpress-assets-map.md`, §1–2)
- [ ] Изображения — `loading="lazy"`, `decoding="async"` там, где были в источнике (все 12 визуализаций вне первого экрана)
- [ ] Читается без JS: контент виден без выполнения скриптов (reveal-анимация в источнике — только косметическое добавление, изначально контент не скрыт — проверить, что WP-реализация сохраняет это свойство, а не прячет секции до срабатывания JS)

## 8. Сквозная интерактивность (см. `elementor-transfer-map.md`, §0)

- [ ] Scroll-spy подсветка активного пункта в ленте разделов работает (или осознанно не реализована — зафиксировать решение)

## 9. Backlog v1.1/v1.2 — НЕ блокирует GO на MVP-перенос

Ниже — 6 пунктов, зафиксированных как открытые во всех исходных документах пакета. Их отсутствие НЕ является причиной ставить NOT GO этому переносу — они закрываются отдельным циклом после MVP:

1. 6 финальных изображений image slots (`hero`, `leak`, `redzone`, `cases`, `materials`, `cta`) — до готовности остаются CSS-сцены.
2. OG-картинка `og-kontur-marzhi.jpg` 1200×630 — до готовности OG-превью будет пустым/дефолтным.
3. Реальный боевой домен вместо `c-level-insight.ru` в canonical/OG/JSON-LD/ссылках на другие технологии.
4. Реальный обработчик формы (в источнике не было даже технического `action` — см. `form-spec.md`, §1,7).
5. Финальные URL материалов (сейчас все 7 карточек — заглушка `#materials`, см. `content-links-map.md`, §6).
6. Решение по схемам 03/05/08/09 — оставлять во внутреннем методическом слое или показывать публично (открытый вопрос из QA визуализаций).
