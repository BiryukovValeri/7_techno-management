# Акт GO на MVP-перенос сайта Контур Маржи

Дата: 2026-08-24

Статус: GO на MVP-перенос в WordPress / Elementor / Novomira.

## 1. Управляющее решение

Сайт технологии `Контур Маржи` передается в MVP-перенос как принятая рабочая версия Claude Design v1.2.

Цель текущего этапа: перенести сайт в WordPress без нового редизайна, без генерации изображений, без изменения art direction, без изменения структуры 19 блоков и без потери mobile / SEO / CTA / материалов / блока `Это не`.

## 2. Что не является блокером MVP-переноса

Следующие пункты не закрываются сейчас и не считаются причиной NOT GO:

1. 6 финальных изображений для image slots:
   - `hero`;
   - `leak`;
   - `redzone`;
   - `cases`;
   - `materials`;
   - `cta`.
2. OG-картинка `assets/og-kontur-marzhi.jpg` или эквивалент 1200x630.
3. Реальный домен вместо placeholder в canonical, OG, JSON-LD и абсолютных ссылках.
4. Реальный обработчик формы WordPress вместо технического `action`.
5. Финальные URL будущих страниц материалов / статей.
6. Решение по схемам 03, 05, 08, 09: оставлять только во внутреннем методическом слое или выводить в публичную страницу.

Эти пункты фиксируются как backlog v1.1 / v1.2 после MVP-переноса.

## 3. Что считается достаточным для MVP-переноса

Для запуска переноса достаточно:

1. актуального HTML / ZIP Claude Design;
2. сохраненной структуры 19 блоков;
3. сохраненного visual / art direction;
4. сохраненного hero;
5. сохраненных визуализаций;
6. сохраненного блока `Материалы`;
7. сохраненного блока `Это не`;
8. сохраненного CTA на платную Диагностику;
9. отсутствия публичного служебного мусора: prompt, placeholder, TODO, browse files, negative prompt;
10. отсутствия горизонтального скролла на mobile после переноса.

## 4. Запреты на этапе MVP-переноса

1. Не редизайнить сайт.
2. Не запускать Claude Design заново.
3. Не генерировать изображения самостоятельно.
4. Не подставлять stock-изображения.
5. Не менять тексты и продуктовую логику.
6. Не превращать Контур Маржи в BI / dashboard / финансовую панель.
7. Не публиковать standalone HTML как финальный production без WordPress QA.

## 5. Первый результат после запуска Novomira

Первым результатом должен быть не финальный production-пуск, а transfer-комплект:

1. `elementor-transfer-map.md`;
2. `wordpress-assets-map.md`;
3. `seo-geo-fields.md`;
4. `form-spec.md`;
5. `content-links-map.md`;
6. `novomira-handoff.md`;
7. `qa-after-transfer.md`;
8. WordPress preview URL, если страница уже собрана.

## 6. Финальный GO на публикацию

Production-публикация выполняется только после отдельного QA на WordPress-preview.

Backlog v1.1 / v1.2 не является причиной остановки MVP-переноса, но должен быть явно указан в отчете после переноса.
