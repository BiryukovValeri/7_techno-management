# Требования К Макету Сайтов C-Level Insight v1.0

Статус: рабочий стандарт визуальной постановки макетов для гигасайта и 7 сайтов технологий. Финальное применение - после утверждения `Visual_Direction_Board_C_Level_Insight_v0.1.md`.

Дата: 11 августа 2026

## 1. Зачем Нужен Этот Документ

Этот документ закрывает риск “скучного сайта”: когда смысл сильный, но Claude Design собирает обычный корпоративный шаблон из hero, карточек и CTA.

Сайт C-Level Insight должен быть не просто аккуратным. Он должен быть визуально убедительным, современным, дорогим и содержательно точным.

Макет обязан показывать:

1. масштаб возможности;
2. авторскую систему;
3. технологическую точность;
4. доказательность через схемы, кейсы и артефакты;
5. визуальное отличие каждой технологии.

## 2. Что Значит “Не Скучный”

“Не скучный” - это не декоративность и не хаос.

Для C-Level Insight это означает:

1. крупный выразительный первый экран;
2. сильный визуальный ритм между секциями;
3. чередование визуальных доминант, схем, текста, кейсов и CTA;
4. 2-3 запоминаемых layout-момента на странице;
5. осмысленные интерактивные паттерны;
6. ощущение авторской системы, а не шаблона;
7. отсутствие однотипной “стены карточек”.

Для текущего направления C-Level Insight “не скучный” означает:

1. гигасайт как карта возможностей;
2. hero как сцена действия;
3. умеренная темная премиальность;
4. технологии как разные визуальные механизмы;
5. motion минимальный и смысловой.

## 3. Hero-Макет

Hero не должен быть обычным текстовым блоком рядом с маленькой картинкой.

Hero должен быть главным визуальным событием страницы.

Допустимые модели hero:

1. full-bleed / крупная фоновая visual opportunity scene с текстом поверх нее;
2. большая управленческая сцена действия с интегрированными смысловыми слоями;
3. архитектурная панель / dashboard-like композиция без BI-штампа;
4. крупная визуализация технологии как first-screen объект;
5. split-layer hero, где изображение, текст и навигация работают как единая сцена, а не как две колонки.

Обязательные условия:

1. на первом экране есть намек на следующий блок;
2. текст читается без борьбы с изображением;
3. CTA видим, но не кричит;
4. mobile-hero не превращается в обрезанный фон;
5. hero показывает возможность, а не болезнь, страх или декоративную абстракцию.

## 5. Библиотека Допустимых Layout-Паттернов

Паттерны выбираются по смыслу технологии, а не ради моды. Аккордеон, tabs, counters, stepper и другие элементы являются только инструментами. Они не являются визуальной ДНК сайта.

Допустимые паттерны:

1. visual hero with full background image;
2. vertical accordion для раскрытия слоев технологии;
3. horizontal stepper для 4 продуктов или спринта;
4. sticky section navigation для длинной страницы;
5. tabs для разделения “что это / как работает / кейсы / материалы”;
6. before / after switcher для изменения управляемости;
7. visualization gallery для схем из `80 Визуализация`;
8. process rail для маршрута Диагностика -> Сессия -> Спринт -> Сопровождение;
9. counters / metric blocks, только если цифры утверждены или являются структурными числами технологии;
10. comparison matrix для анти-категорийного блока;
11. case flow для кейсов;
12. layered blueprint для сложных схем;
13. editorial dossier section для объяснения технологии;
14. CTA band как отдельная сильная полоса, а не маленькая карточка.

Запрещено:

1. использовать все паттерны сразу;
2. ставить интерактив ради украшения;
3. делать вертикальный аккордеон там, где нужна простая схема;
4. использовать счетчики без смысла и источника;
5. превращать сайт в набор одинаковых карточек;
6. подменять визуальный механизм технологии набором модных компонентов.

## 6. Минимум Визуальной Постановки Для Сайта Технологии

Каждый сайт технологии должен иметь:

1. один сильный hero;
2. минимум 3 визуализации из `80 Визуализация`;
3. минимум 2 будущих изображения с промптами для генерации / поиска;
4. минимум 2 осмысленных интерактивных паттерна;
5. один сильный блок “что это / что это не”;
6. один блок кейса или примера как доказательство;
7. один продуктовый маршрут 4 продуктов;
8. одну финальную CTA-секцию на платную Диагностику.

## 7. Минимум Визуальной Постановки Для Гигасайта

Гигасайт должен иметь:

1. премиальный hero с тремя входами: технологии, кейсы, связки возможностей;
2. систему 7 технологий как визуальную карту, а не каталог карточек;
3. блок синергетических связок как “1 + 1 = 3”;
4. кейсовую библиотеку как доказательство применимости;
5. отдельный раздел материалов / ленты;
6. авторский слой доверия без превращения сайта в личную визитку;
7. визуальный уровень выше сайтов технологий.

## 8. Изображения И Визуализации В Макете

В макете должны быть разведены два типа активов.

**Визуализации**:

1. берутся из папки `80 Визуализация`;
2. объясняют технологию;
3. используются как схемы, карты, visual masters;
4. требуют подписи и mobile-адаптации.

**Изображения**:

1. создаются или подбираются отдельно;
2. дают эмоциональную и визуальную сцену;
3. используются для hero, фона, обложек, разделов;
4. требуют промпта и негативного промпта.

Нельзя заменять одно другим.

## 9. Mobile-Макет

Команда обязана описать mobile-поведение каждого ключевого блока.

Проверки:

1. нет горизонтального скролла;
2. hero не превращается в нечитаемую обложку;
3. визуализации имеют mobile-версию или раскрываются фрагментами;
4. аккордеоны и tabs имеют нормальные touch targets;
5. CTA не перекрывает контент;
6. длинные таблицы заменяются карточками или последовательными блоками;
7. текст не становится мелким ради сохранения desktop-макета.

## 11. Формула Для Claude Design

В финальном промпте должна быть фраза:

> Создай визуально сильный, премиальный и современный сайт C-Level Insight, а не скучный корпоративный шаблон. Сайт должен иметь выразительный hero, карту макета, визуальные доминанты, осмысленные интерактивные паттерны, готовые визуализации из `80 Визуализация`, отдельные будущие изображения с промптами и продуманную mobile-версию. Не сокращай сайт до набора карточек и стандартных секций.
