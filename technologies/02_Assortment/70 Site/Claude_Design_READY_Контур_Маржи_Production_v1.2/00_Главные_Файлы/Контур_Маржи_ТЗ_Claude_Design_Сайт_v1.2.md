# Контур Маржи. ТЗ Для Claude Design На Сайт Технологии v1.2

Статус: актуальное управляющее ТЗ после проверки первого варианта сайта.

## 1. Главная Задача

Создать полноценный визуально сильный сайт технологии `Контур Маржи` на базе принятой `C-Level Insight Design System`.

Сайт должен продавать не финансовую панель и не BI, а авторскую технологию управления ассортиментной прибылью в омниканальных продажах.

Главный смысл:

`Контур Маржи помогает увидеть, где товар / SKU / канал теряет управляемую прибыль, и перевести красную зону в владельца, решение, проверку и эффект.`

## 2. Что Исправить После Первого Макета

Первый вариант сайта не принимается как production-макет, потому что:

1. визуально слишком сухой;
2. недостаточно использует visual code принятой Design System;
3. почти не использует изображения как эмоциональный и смысловой слой;
4. визуализации встроены слишком документно;
5. нет отдельного блока `Материалы / Блог / Разборы`;
6. motion / animation почти не считываются;
7. hero выглядит как текстовая обложка, а не как визуальное событие;
8. сайт не создает ощущения современной премиальной технологии.

Задача v1.2: не переписать смысл, а поднять визуальный и продуктовый уровень макета.

## 3. Design System

Использовать только:

`C-Level Insight Design System`

Рабочий стиль:

1. Executive Blueprint - структурная точность;
2. Opportunity Control Room - управленческая карта и навигация;
3. Cinematic Technology Cabinet - один сильный визуальный слой, не весь сайт.

Не создавать:

1. generic consulting template;
2. BI / dashboard / SaaS-панель;
3. финансовый аудит;
4. Excel-сайт;
5. обычный корпоративный лендинг;
6. сайт из одинаковых карточек.

## 4. Hero

Hero должен быть большим визуальным событием.

Требования:

1. full-bleed или почти full-bleed визуальная сцена;
2. текст поверх или внутри сцены, но без потери читаемости;
3. видимый намек на следующий блок;
4. CTA: `Запросить платную Диагностику`;
5. secondary CTA: `Посмотреть, как работает контур`;
6. hero не должен выглядеть как сухой текстовый блок.

Hero image prompt:

`Premium cinematic management surface for margin control: a dark navy executive table, a clean copper margin line moving through product/channel nodes, several subtle red leakage zones becoming visible, teal owner markers appearing near decision points, warm paper texture, precise blueprint grid, no dashboard, no Excel, no people, no handshake, no readable text inside image, 16:9, premium consulting technology visual.`

Negative prompt:

`no BI dashboard, no spreadsheet, no charts with numbers, no office people, no handshake, no robots, no neon, no stock business photo, no readable text, no medical metaphor.`

## 5. Обязательные Разделы Сайта

Сайт должен содержать:

1. Header;
2. Hero;
3. `Что открывает Контур Маржи`;
4. `Ситуация клиента`: выручка видна, управляемая маржа - нет;
5. `Ядро технологии`;
6. `Где течет маржа`;
7. `Красная зона и владелец`;
8. `Что это / что это не`;
9. `Как работает`: Диагностика -> Сессия -> Спринт 30-60-90 -> Сопровождение;
10. `Визуализации`;
11. `Кейсы / модельные сценарии`;
12. `Материалы / Блог / Разборы`;
13. `Стоимость и границы`;
14. FAQ;
15. CTA на платную Диагностику;
16. форма заявки;
17. Footer с C-Level Insight и 7 технологиями.

## 6. Материалы / Блог / Разборы

Раздел обязателен.

Назначение:

1. SEO / GEO актуализация сайта;
2. размещение статей и разборов;
3. вход в vc.ru / dzen.ru / Telegram / MAX / VK;
4. поддержание сайта живым, а не статичным.

Минимальный состав:

1. `Разборы маржи`;
2. `Кейсовые заметки`;
3. `Ошибки управления ассортиментной прибылью`;
4. `Связки с другими технологиями C-Level Insight`;
5. CTA: `Получить разбор своей ситуации через Диагностику`.

Сделать 3-4 карточки статей с готовыми заголовками, датой-заглушкой без фальшивой фактичности и тегами.

## 7. Визуализации

Встроить все 12 PNG из папки `30_Визуализации`, но не превращать сайт в галерею картинок.

Обязательная логика:

1. 4-5 ключевых визуализаций раскрыть внутри основных секций;
2. остальные собрать в `Галерею визуализаций`;
3. каждая визуализация имеет подпись;
4. на mobile визуализация открывается в readable mode / enlarged view / фрагментированном просмотре;
5. не растягивать PNG так, чтобы схема теряла читаемость.

## 8. Изображения

Кроме визуализаций, сайт должен иметь 3-5 будущих изображений.

Для каждого изображения дать:

1. место в сайте;
2. prompt;
3. negative prompt;
4. назначение изображения.

Минимум:

1. hero image;
2. image для `Где течет маржа`;
3. image для кейсового блока;
4. image для финального CTA.

Изображения не должны содержать читаемый текст.

## 9. Motion / Interaction

Motion нужен минимальный, но считываемый.

Использовать:

1. sticky section navigation;
2. плавное раскрытие визуализаций;
3. before / after switcher для средней маржи и управляемой маржи;
4. hover states на карточках кейсов и материалов;
5. мягкий reveal секций;
6. reduced-motion support.

Не использовать тяжелый parallax, scroll-jacking, декоративный хаос.

## 10. CTA И Диагностика

Диагностика - первый платный вход.

Не писать так, будто это бесплатный аудит, бесплатная стратегическая сессия или скрытый тест.

CTA:

1. `Запросить платную Диагностику`;
2. `Проверить контур маржи`;
3. `Разобрать красные зоны`.

## 11. Self-QA На Выходе

В конце работы дать Self-QA:

1. сайт не похож на generic consulting template?
2. сайт не ушел в BI / dashboard / financial audit / Excel?
3. hero является визуальным событием?
4. есть блок `Материалы / Блог / Разборы`?
5. есть 3-5 image slots с prompt / negative prompt?
6. визуализации встроены как смысловые схемы?
7. mobile-версия читабельна?
8. motion есть, но не перегружает?
9. все тексты готовы, без placeholder?
10. макет пригоден для WordPress / Novomira?
