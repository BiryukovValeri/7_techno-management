## 1. Название технологии

Публичное название: **AI переход**.

Пояснение при первом упоминании: **AI переход — управленческая технология допуска искусственного интеллекта, ИИ, к бизнес-решениям компании**.

Короткая формула сайта: **Сначала управляемость, потом ИИ**.

Что продает сайт: не внедрение инструмента, а право запускать ИИ управляемо: через задачу, готовность, данные, владельца эффекта, риск, экономику, ограниченный активный набор и контроль после запуска.

Первый платный продукт: **Диагностика применимости AI перехода**.

## 3. Смысловое ядро

AI переход нужен компании, которая уже чувствует давление внедрять ИИ, но не хочет покупать витрину, обучение или набор пилотов без управленческого результата.

Сайт должен открыть клиенту одну управленческую победу:

> Компания может не спорить об ИИ вообще, а получить проверяемое решение: что запускать, что запускать при условиях, что отложить и что остановить.

Ядро технологии:

```text
задача -> готовность -> данные -> владелец эффекта -> риск -> экономика -> ограниченный набор AI-сценариев, сценариев применения ИИ -> внедрение -> контроль
```

Сайт должен удерживать четыре смысловые опоры:

1. ИИ без управленческого контура ускоряет хаос.
2. Первый шаг — платная Диагностика применимости, а не выбор инструмента.
3. Активный набор ограничен: лучше до 5 управляемых вариантов, чем десятки шумных идей.
4. Запуск не считается результатом без владельца эффекта, данных, условий остановки и контроля.

## 5. Что сайт должен открыть клиенту

Главный переход восприятия:

```text
“Нам срочно нужен ИИ” -> “Нам нужно понять, можно ли запускать ИИ управляемо”
```

Живой язык клиента:

| Как клиент говорит | Что за этим стоит | Ответ сайта |
|---|---|---|
| Мы уже пробуем ИИ, но непонятно, где эффект | Активность есть, управленческого результата нет | Пилоты без владельца эффекта надо проверять до расширения |
| Нам надо стать AI-first | Есть амбиция, но нет критериев готовности | Сначала управляемость, потом ИИ |
| Сотрудники используют ChatGPT кто как умеет | Навык ушел впереди правил, данных и ответственности | Обучение инструментам не заменяет управленческий допуск |
| Автоматизируйте нам процесс | Клиент может не видеть, какое решение должно измениться | Автоматизация старого хаоса только ускоряет ошибку |
| Нам нужна стратегия ИИ | Клиент ищет уверенность, но может купить слишком широкую программу | Начать с Диагностики применимости |
| Как понять, что это окупится | Финансовая дисциплина важнее обещаний | Нужны базовая линия, показатель, источник данных, период и владелец эффекта |

## 7. Визуальная постановка

### 7.1. Обязательная визуальная логика

Visual direction: **Precision Instrument + Cinematic Action Scene**.

Главная механика: **Decision Path / контур допуска**.

Hero-сцена действия: **AI входит в работу только через управляемый контрольный контур**.

Вспомогательные механики:

1. layered reveal, последовательное раскрытие слоев допуска;
2. control panel, панель управленческого контроля;
3. before / after switcher, переключение состояния до и после управляемого допуска;
4. product ladder, продуктовая лестница Диагностика -> Сессия -> Спринт -> Сопровождение.

Motion: минимальный. Разрешено только раскрытие допуска, подсветка контрольного контура и переход состояния “хаотичные инициативы -> управляемый активный набор”.

Запрещено: роботы, неон, интерфейс ChatGPT, набор AI-логотипов, stock-office, рукопожатия, медицинские метафоры, футуристическая витрина без управленческого смысла.

### 7.2. Hero-драматургия: 3 варианта

| Вариант | Сцена | H1 | Подзаголовок | CTA | Когда использовать |
|---|---|---|---|---|---|
| A. Контур допуска | Темная управленческая сцена: поток AI-инициатив входит в точный контрольный контур, где выделены задача, данные, владелец, риск, экономика, контроль | Сначала управляемость, потом ИИ | AI переход проверяет, можно ли компании запускать ИИ управляемо: с задачей, данными, владельцем эффекта, риском, экономикой и контролем | Запросить Диагностику / Посмотреть, как работает | Основной вариант |
| B. От шума к пяти вариантам | Много разрозненных AI-карточек сжимается в пять управляемых слотов активного набора | От десятков AI-идей к пяти управляемым вариантам | Технология отсекает шум и оставляет только те варианты применения ИИ, которые можно реализовать и контролировать | Проверить применимость / Посмотреть активный набор | Для акцента на Сессии |
| C. H2: `Когда компании нужен AI переход`

Список:

1. Есть пилоты, но нет владельца эффекта.
2. Есть идеи, но нет активного набора.
3. Есть данные, но нет владельца данных и правила реакции.
4. Есть ожидание эффекта, но нет базовой линии.
5. Есть страх отстать, но нет управленческого мандата.
6. Есть внедрение, но нет контроля после запуска.

#### Блок “Что это / что это не”

H2: `AI переход — не курс и не витрина`

Короткая формула:

`AI переход — это не курс по ChatGPT, не список промптов и не набор разрозненных AI-пилотов. Технология работает не с модой на инструменты, а с управленческим допуском ИИ к реальным решениям компании.`

Матрица:

| Не является | Как правильно понимать |
|---|---|
| не курсом по ChatGPT | как управленческую технологию проверки применимости ИИ до запуска |
| не списком промптов | как способ связать ИИ с задачей, данными и владельцем эффекта |
| не набором AI-пилотов | как фильтр допуска к ограниченному активному набору вариантов |
| не покупкой AI-инструментов | как проверку права запускать инструмент в конкретном управленческом контуре |
| не цифровой модой без управленческого эффекта | как дисциплину решения: запускать, запускать при условиях, отложить или остановить |

## 15. Mobile / responsive

Общие правила:

1. Нет горизонтального скролла.
2. Body text не меньше 16px.
3. Touch targets не меньше 44px.
4. Hero не превращается в обрезанный фон.

Для ключевых блоков:

| Блок | Mobile-поведение |
|---|---|
| Hero | текст над сценой, контрольный контур в центре, CTA в одну колонку |
| Ядро | layered reveal по одному слою |
| Продукты | вертикальный stepper |
| “Что это / что это не” | пары “не является / правильно понимать” |
| Визуализации | одна схема на экран, подпись под схемой |
| Кейсы | фильтр сверху, карточки вертикально |
| Форма | 6 полей, visible labels, ошибки под полем |

## 17. Ограничения и запреты

## 19. Финальный промпт для Claude Design

Создай полный сайт технологии **AI переход** для экосистемы C-Level Insight.

Это не каркас и не черновой wireframe. Это сайт под ключ на основе утвержденного ТЗ. Используй весь контент из файла, не сокращай страницы до тезисов, не заменяй тексты пустыми блоками и не придумывай новые смыслы.

### Обязательная смысловая рамка

AI переход — управленческая технология допуска искусственного интеллекта, ИИ, к бизнес-решениям компании.

Главная формула: **Сначала управляемость, потом ИИ**.

Ядро: задача -> готовность -> данные -> владелец эффекта -> риск -> экономика -> ограниченный набор AI-сценариев, сценариев применения ИИ -> внедрение -> контроль.

Первый платный продукт: **Диагностика применимости**.

Сайт должен вести клиента к пониманию: перед запуском ИИ нужно проверить, можно ли запускать его управляемо.

### Обязательная визуальная логика

Visual direction: **Precision Instrument + Cinematic Action Scene**.

Главный visual mechanism: **Decision Path / контур допуска**.

Hero-сцена: AI входит в работу только через управляемый контрольный контур.

Вспомогательные механики: layered reveal, control panel, before / after switcher, product ladder.

Motion минимальный: только раскрытие допуска, контрольного контура и перехода состояния. Не делать motion ради wow.

### Обязательная структура

Создай страницы / секции:

1. Главная.
2. Технология.
3. Диагностика.
4. Сессия решений.
5. Спринт 30-60-90.
6. Сопровождение контроля.
7. Кейсы.
8. Визуализации и материалы.
9. FAQ.
10. Заявка на Диагностику.

Для каждой страницы используй готовые H1, подзаголовки, тексты, CTA, SEO title и meta description из ТЗ.
