## 2. Final site set
Default approved Technology Visualizations for the public site:

**TV-02 — Переговорное поле**
Function: show that decision power is distributed across external and internal participants, interests, constraints and authority.
Primary placement: Home H04 or Technology T03. Do not duplicate on both unless one instance is a reduced crop.

**TV-05 — BATNA / ZOPA**
Function: show two different decision spaces — outside agreement vs inside potential agreement — plus bad-agreement boundary, pause and exit.
Primary placement: Technology T05–T07; Home may use a reduced explanatory crop only if necessary.

**TV-06 — Карта уступок**
Function: show that concession is not binary; it has cost, condition, counterstep and authority.
Primary placement: Technology T08. This visual is now promoted into the core site set because the rebuilt narrative gives concessions a distinct causal role.

**TV-12 — Антипозиционирование**
Function: protect category: not training, scripts, manipulation, motivational session, legal opinion or financial audit.
Primary placement: Technology T14 or About/Project. Supporting, not core mechanism.

Maximum default = 4 source Technology Visualizations. Do not add more from the 12-slide library without reopening the visual architecture.

## 3. Explicit exclusions
Never place source visuals 03, 07, 09 or 11 on the current site as-is.
They contain superseded commercial/product routing.
Do not “fix” them by deleting one label inside the image; that would create a new derived visualization. If Owner later wants one, rebuild from current Content Master as a new version with provenance.

## 4. Relationship to page narrative
Technology Visualizations are inserted only at points where they compress a complex causal relationship:

Home/Technology:
unmanaged position → [TV-02 field] → 10-step mechanism → [TV-05 BATNA/ZOPA] → [TV-06 concessions] → decision/risk/loop → [TV-12 anti-category].

The visual must never interrupt the causal chain merely because an asset exists.

## 5. Image Slots
No decorative image is required for:
- products;
- tools/forms;
- FAQ;
- evidence/boundaries;
- contact;
- case detail pages.

Cases may have an optional contextual Image Slot only when it clarifies the actual modeled situation. They must remain fully understandable without it.
Author portrait only if a real Owner-approved portrait is supplied.
Articles may have optional editorial images later; no fake article bodies or stock visual system now.

## 6. Source slide chrome
Source slides contain presentation chrome: upper rail, layer/type/complexity, legend, filename, author footer and “ЭТО НЕ”.
For website use, do NOT blindly place the entire slide screenshot if the chrome harms readability/responsiveness.
Preferred implementation:
- preserve the source diagram semantics and labels;
- use the approved PNG as source reference;
- rebuild/crop responsively only when no semantic content is changed;
- do not invent new nodes/metrics/claims;
- on mobile, preserve the central explanatory relationship rather than shrinking a 16:9 slide to illegibility.

## 7. Responsive requirement
One semantic visualization must survive Desktop / Tablet / Mobile.
Do not create three different meanings.
Allowed: responsive crop/reflow of the same semantic structure.
Not allowed: mobile version that removes BATNA, ZOPA, internal contour, counterstep or another essential relation.

## 8. Acceptance test
For every Technology Visualization ask:
1. What exact relationship does it explain?
2. Is that relationship hard to understand from text alone?
3. Does the source visual still match current ontology?
4. Does it introduce obsolete product routing, price, duration or guarantee?
5. Can the meaning survive mobile?
6. Would the page become clearer if the visual were removed?

If #1 has no precise answer, or #3/#4 fail, do not use the visual.
