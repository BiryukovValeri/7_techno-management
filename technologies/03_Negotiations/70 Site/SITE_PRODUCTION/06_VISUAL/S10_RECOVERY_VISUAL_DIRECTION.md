## 0. Governing correction
The 12 source visualizations are a presentation/source library. They are NOT twelve website images.

Website visual production distinguishes:
1. HERO IMAGE — approved first-screen artwork.
2. TECHNOLOGY VISUALIZATION — source-derived explanatory image of a real technology relation.
3. IMAGE SLOT — independent comprehension image for a specific content block.
4. DECORATIVE — permitted only where it does not pretend to explain/prove technology; default is avoid.
5. NO IMAGE.

Target: **3 core Technology Visualizations; a fourth only if it earns its place.**
No quota for Image Slots. If an image does not improve comprehension, use NO IMAGE.

## 2. Technology Visualization production contract
A source visualization can enter web production only after a separate preservation contract records:
- source file identity;
- public communication question;
- mandatory semantic nodes;
- mandatory relations;
- mandatory sequence/direction where applicable;
- canonical public terminology;
- presentation chrome removable;
- allowed web recomposition;
- forbidden semantic changes;
- mobile semantic reconstruction;
- source-vs-web diff acceptance.

The web adaptation is a distinct asset class: **WEB ADAPTATION OF SOURCE TV**, never silently labeled the source original.

Claude Design may redesign composition but may not invent/reinterpret semantic structure.

## 3. TV-01 candidate — source 01
### Communication question
«Из каких связанных управленческих объектов складывается переговорная позиция компании?»

### Required web meaning
Negotiation position is an architecture of connected objects rather than speaking technique.

### Mandatory public nodes
At minimum the source-supported public entities represented in T1/C:
- goals/interests/success criteria;
- participant/side context;
- influence/power/authority;
- BATNA;
- ZOPA;
- concessions/countersteps;
- cognitive risks where source architecture supports them;
- next decision/scenario and fixation/next cycle only if present in source relation.

Exact source-node inventory must be checked against the actual source visual before adaptation. This document does not fabricate missing diagram nodes.

### Allowed
Remove slide rail, layer/type/complexity labels, file name, author footer, presentation legend where non-semantic; recompose for web; translate public labels under language gate.

### Forbidden
Turn into feature grid; add metrics/scoring; add AI/software UI; add new technology entities; make it a product map.

### Placement
Primary: Technology page architecture act. Home may use a lighter HTML preview instead of duplicating full TV.

## 7. Image Slot architecture
Image Slot is not a source Technology Visualization and is not a derivative of Hero by default.
Each slot must have a one-sentence comprehension function before design.

### IS-PRODUCTS — CONDITIONAL
Function: help perceive the difference among four ways of working without implying sequence.
If an image cannot clarify that distinction better than information design → NO IMAGE.
Forbidden: ladder, staircase, funnel, four Hero-like objects.

### IS-TOOLS — JUSTIFIED CANDIDATE
Function: make visible that Forms 17–23 are material working instruments used through real decision work.
Image may show document/work-material reality but must not fabricate readable form content.
Required HTML remains source of names/roles.
Forbidden: blank premium-paper still life as “proof”; fake screenshots; Hero dossier clone.

### IS-CASE — CONDITIONAL
Function: orient the reader to the management situation of a case.
Must be case-specific enough to aid comprehension.
Forbidden: generic negotiation artwork repeated across 12 cases; client-success imagery; invented brands/people/results.
If no case-specific semantic subject exists → NO IMAGE.

### IS-ARTICLE — CONDITIONAL
Function: explain the article subject or conceptual relation.
No mandatory cover image system.
Decorative cover without comprehension value → NO IMAGE.

### IS-ABOUT — DEFAULT NO IMAGE
No invented corporate/team photography. Author image only from verified owner-supplied/source asset.

## 8. Hero containment rule
Hero is a singular approved artwork.
It may inform quality level and broad palette compatibility, but NOT automatically:
- object vocabulary;
- dossier/paper composition;
- compass/pen motif;
- route-map metaphor;
- layered-document metaphor;
- scene construction of other images.

Using repeated Hero objects/metaphor across Image Slots = HERO_CLONING.

## 9. Visual language vs visual metaphor
Allowed cross-site consistency:
- approved palette after Design System lock;
- typography system;
- line/edge discipline;
- density/rhythm;
- surface treatment where appropriate;
- icon family.

Not automatically inherited:
- Hero scene;
- Hero props;
- Hero narrative;
- Hero spatial metaphor.

## 10. Presentation chrome removal
Source slides contain presentation-only elements: top rail, visualization number/layer/type/complexity, file labels, author footer and other slide framing.
These are not website content unless separately required semantically.
Removing them is not semantic loss.

## 11. Website text rule
Critical explanatory copy stays HTML whenever practical.
Do not bake long Russian text into generated/raster imagery.
Source visual adaptations may contain concise labels necessary for relations; labels must pass public language and accessibility checks.

## 12. Responsive rule
Do not shrink a 16:9 presentation slide into unreadable mobile.
For each TV adaptation:
desktop composition → tablet semantic simplification → mobile semantic reconstruction.
Nodes/relations/order required by preservation contract must survive.
If they cannot survive visually, use HTML-assisted composition rather than deleting meaning.

## 13. Pilot gate before scale
Before producing all non-Hero assets:
1. choose ONE Technology Visualization candidate (prefer TV-02 or TV-03 after exact source inspection);
2. create one web adaptation;
3. independently compare source semantics vs adaptation;
4. choose ONE justified Image Slot (prefer IS-TOOLS);
5. create one image;
6. test whether it improves block comprehension and is not Hero cloning;
7. Owner/independent acceptance;
8. only then scale remaining visual production.

No batch generation before this pilot gate.
