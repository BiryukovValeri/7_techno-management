# DESIGN_INTENT_ARCHITECTURE — Архитектура Переговоров
Status: QR-06 / REPLACES GENERIC S06 AS DESIGN AUTHORITY
Date: 2026-10-01
Stack feasibility: WordPress + Blocksy + Elementor Free
Authority: T1 + M + H + A/C locks + QR Public Knowledge Architecture + Public Language Gate

## 0. Why this replaces old S06
The former S06 proved Elementor feasibility but described pages mainly through generic containers/grids/cards. That is insufficient production control: a block can exist and still fail to explain the technology.

This document controls **knowledge transfer and design intent**.
It does NOT prescribe a pixel layout and does NOT ask Claude Design to think in Elementor primitives.

For each meaningful act:
- comprehension job;
- information hierarchy;
- semantic relationships;
- required content;
- visual role;
- responsive invariant;
- forbidden transformation;
- design freedom.

Implementation primitives are chosen after visual design is approved, within the locked stack.

## 1. Global design laws
1. Site first explains the technology; it is not a gallery, slide deck or generic consulting landing page.
2. Hero Image, Image Slot and Technology Visualization are different entities.
3. Technology Visualization is used only where the actual mechanism/relationship needs visual explanation.
4. Image Slot exists only when an image improves comprehension of that block. No function = NO IMAGE.
5. Target is 3–4 Technology Visualizations across the site, not all 12 source slides.
6. Hero establishes first-screen identity but its object/metaphor must NOT be cloned through the site.
7. Required knowledge survives responsive design. Mobile may recompose, not delete.
8. Russian public language gate applies to every visible element and readable asset text.
9. Exactly four products. No automatic funnel.
10. Cards/grids are possible design devices, never the semantic specification.

## 2. Global shell
### Header
Job: orientation + fast access to core knowledge + contact action.
Required: Технология / Продукты / Кейсы / Инструменты / Статьи; CTA «Обсудить ситуацию».
Secondary/trust destinations remain reachable: О проекте / Об авторе / FAQ / Контакты.
Invariant: no destination disappears because desktop menu is crowded.
Forbidden: invented «Инструменты» destination beyond the actual Forms 17–23 page; English nav labels.
Freedom: navigation presentation, grouping, mobile behavior.

### Footer
Job: complete orientation, provenance/trust and conversion support.
Required: core knowledge destinations + four products + About/Author/FAQ/Contact + legal/privacy when current implementation requires.
Forbidden: invented company/legal facts.
Freedom: composition.

## 3. HOME — major semantic acts
Home is not 12 equal stacked sections. Claude must compose a coherent reading rhythm from the following acts.

### H-ACT-01 — First perception / Hero
Comprehension: this is a management technology for creating a strong company negotiation position before the decision.
Hierarchy: governing message → short explanation → primary action.
Required: H/C locked Hero copy and FINAL H-LOCK artwork.
Visual role: HERO IMAGE only.
Invariant: left copy / right-art semantic relationship on desktop; mobile copy and action precede art; approved art identity survives crop.
Forbidden: regenerate Hero, add fake UI/metrics, compete with artwork using dense text, reuse Hero object language as site-wide image formula.
Freedom: typography/spacing/precise composition within H-lock.

### H-ACT-02 — What is actually managed
Comprehension: negotiation position is a system of connected decision objects, not speaking skill alone.
Hierarchy: managed position → goal/criteria → authority → alternative/BATNA → ZOPA/bad-agreement boundary → influence → concessions/countersteps → risks → next decision.
Relationship: objects are connected parts of one position, not unrelated features.
Visual role: primarily information composition. No image required. A Technology Visualization is allowed only if selected SV-01 proves it explains this relation better than HTML composition.
Invariant: all core objects remain understandable on mobile.
Forbidden: icon soup, eight decorative cards with no relation, personality profiling.
Freedom: visual grammar showing relation.

### H-ACT-03 — One core / two fields
Comprehension: external negotiation and internal alignment are two fields of one technology; internal decisions affect external position.
Relationship: ONE CORE → EXTERNAL + INTERNAL, with connection between them.
Required: source-backed contour examples only.
Visual role: candidate TECHNOLOGY VISUALIZATION SV-02 if it passes preservation gate. Not an Image Slot.
Invariant: relationship survives mobile; must not become two separate technologies.
Forbidden: two-product/two-method interpretation; org-chart invention.
Freedom: web composition around preserved semantic relation.

### H-ACT-04 — How the technology works
Comprehension: the position is built and updated through the canonical 10-step cycle.
Hierarchy: situation/error price → goals/interests/success criteria → participant profile → influence/power → BATNA → ZOPA → concessions/roles → cognitive risks → next-decision scenario → fixation/review/next cycle.
Relationship: ordered cycle, not ten independent services.
Visual role: one primary TECHNOLOGY VISUALIZATION may carry this act only if source semantic asset supports the full relation; otherwise HTML-led route plus a source-derived visual supporting subset.
Invariant: order and cyclic return survive all breakpoints.
Forbidden: shortening into an invented 4/5-step method; making steps purchasable; unreadable shrunk desktop diagram.
Freedom: visual route/cycle composition.

### H-ACT-05 — Good decision is not agreement at any price
Comprehension: a controlled negotiation can legitimately end in several decisions, including pause/refusal.
Hierarchy: principle first; outcomes second.
Relationship: outcomes are legitimate branches from evidence/conditions, not maturity levels.
Visual role: NO IMAGE by default. Use information design.
Invariant: refusal/pause remains equally legitimate, not visually marked as failure.
Forbidden: imported Go/Hold/Stop ontology; funnel/progress ladder.
Freedom: branch/status composition in Russian.

### H-ACT-06 — Materiality: Forms 17–23
Comprehension: the technology has concrete working instruments connecting preparation, decision and post-negotiation learning.
Relationship: seven forms form a connected working system; they are not seven products.
Visual role: IMAGE SLOT is justified only if it helps perceive material working artifacts; source Technology Visualization only if selected for an actual semantic relation. Image cannot replace names/roles in HTML.
Invariant: Forms 17–23 and their distinct roles survive.
Forbidden: generic blank-paper mockups as proof; download-store framing; Form 24.
Freedom: artifact presentation and information hierarchy.

### H-ACT-07 — Applicability / evidence / cases
Comprehension: the technology can be examined through bounded checks and model situations without claiming guaranteed outcomes.
Hierarchy: evidence boundary → selected model cases → route to all 12.
Visual role: Case IMAGE SLOT only when tied to the specific management situation; no generic Hero-style abstraction. It is optional.
Invariant: model/teaching disclosure remains visible.
Forbidden: testimonials, real-client implication, before/after effect imagery, metrics not in source.
Freedom: how selected cases are editorially surfaced.

### H-ACT-08 — Four ways to work + entry
Comprehension: one technology can be applied in four formats selected by situation; sequence is not mandatory.
Required exactly: Диагностика / Сессия / Спринт / Сопровождение.
Relationship: four modes around one technology, not four ladder stages.
Visual role: no decorative image required. A contextual Image Slot is allowed only if it genuinely clarifies distinctions among modes.
Invariant: all four equal ontology status; conditional selection remains clear.
Forbidden: fifth product, funnel arrows, fixed purchase journey, universal duration/price.
Freedom: comparative/product composition + CTA.

### H-ACT-09 — Knowledge / provenance
Comprehension: deeper explanation exists beyond Home and the technology has an explicit project/provenance layer.
Required: Articles entry + About Project; Author only once verified content exists; FAQ/Contact reachable.
Visual role: NO IMAGE by default.
Forbidden: fake article inventory, fabricated author biography.
Freedom: editorial composition.

## 4. TECHNOLOGY PAGE
### T-ACT-01 Definition and object
Must establish technology, managed object and boundary from training/tricks.
Visual: no image required.

### T-ACT-02 Architecture of position
Must show relationships among goal, authority, BATNA, ZOPA, influence, concessions, risks and next decision.
Candidate: SV-01 if preservation test passes.
Forbidden: unrelated feature cards.

### T-ACT-03 One core / two fields
Candidate: SV-02.
Same invariants as Home; if full visualization is used on Technology, Home should use a lighter HTML preview rather than duplicate the same large diagram.

### T-ACT-04 Canonical cycle
Fullest public explanation of 10 steps.
Required ordered/cyclic relationship.
No protected operating detail beyond disclosure.

### T-ACT-05 BATNA / ZOPA / bad-agreement boundary
Comprehension: these are distinct concepts and jointly constrain a decision.
Candidate TECHNOLOGY VISUALIZATION: SV-03 (source 05).
Invariant: BATNA != ZOPA; agreement is not inherently success.
Forbidden: promise that overlap guarantees agreement.

### T-ACT-06 Instruments and decision outcomes
Forms connect to real work; outcomes show controlled decision space.
No automatic mapping invented where source does not establish it.

### T-ACT-07 Boundaries
Constructive anti-category.
SV-04 only if it explains more than text; otherwise NO IMAGE.
Forbidden: use visual just to reach “four”.

### T-ACT-08 Application
Four products as application formats.
No funnel.

## 5. TOOLS PAGE
Comprehension job: show Forms 17–23 as material instruments across one negotiation cycle.
Hierarchy: why instruments exist → seven roles → relation to cycle → relation to work/products only where source supports → disclosure boundary.
Semantic relationship: connected system, not card catalog.
Visual role: one contextual artifact Image Slot may be useful; it must show materiality, not pretend to be evidence. Technology Visualization only if an actual source diagram adds understanding.
Responsive invariant: roles remain distinct and sequence/context understandable.
Forbidden: seven identical cards as entire explanation; fake form screenshots; Form 24; standalone spreadsheet product framing.
Freedom: editorial/diagrammatic presentation.

## 6. PRODUCTS
### Index
Comprehension: four different depths/modes of applying one technology; choice depends on situation.
Required distinctions: role / when used / work object / output / boundary.
Visual: contextual product Image Slot only if it clarifies difference; otherwise no image.
Forbidden: pricing/duration without current approval; funnel.

### Detail template
Comprehension sequence:
role → when used → inputs → work → outputs → relevant instruments if sourced → possible decisions → boundaries → relevant case/evidence if approved → contact.
Visual: product-specific Image Slot only with explicit semantic function.
Forbidden: decorative repeated Hero metaphor; guaranteed KPI/result.

## 7. CASES
### Index
Comprehension: breadth of model situations and how the technology is applied, not social proof.
Required: all 12 discoverable once QR-03 bodies close; model/teaching disclosure.
Visual: imagery optional; function is situational orientation, not decoration.
Forbidden: only 3 cases presented as if corpus ends there; client-logo/testimonial language.

### Detail
Two reading depths are mandatory:
1. short reading layer;
2. full public-safe source-derived body.
Summary cannot replace full body.
Visual must not imply real client evidence.
Responsive: full body remains available; mobile cannot collapse it into summary-only.

## 8. ARTICLES
Comprehension: deepen one source-grounded management question and connect it to canonical technology entities.
Required per published article: clear question/topic, source-grounded explanation, boundaries, meaningful internal links.
Visual: article image only if it helps explain subject; no mandatory decorative cover system.
Forbidden: generated filler, invented statistics/claims, pages created only to fill taxonomy.
Freedom: editorial layout.

## 9. ABOUT / AUTHOR / CONTACT
### About Project
Explain technology/project provenance, scope and public structure from T1/M/C.
No invented history/market achievements.

### Author
Architecture exists; content HOLD until verified.
Design must tolerate unavailable author content without fake placeholder biography.

### Contact
Explain what to bring to first discussion and provide only verified routes.
No fake channel/form endpoint.

## 10. Visual-class decision gate
Before assigning any visual to a block ask:
1. Is this the FINAL Hero? → HERO IMAGE.
2. Does a source diagram explain an actual technology relationship? → TECHNOLOGY VISUALIZATION, preservation contract required.
3. Does a standalone image materially improve comprehension of this block? → IMAGE SLOT with explicit function.
4. Otherwise → NO IMAGE.

No asset is created merely because the layout has empty space.

## 11. Responsive semantic invariants
Across all pages:
- required entities cannot disappear;
- relationship cannot turn into unrelated stacked cards;
- ordered mechanisms retain order;
- two-contour relation remains explicit;
- four products remain four peer formats;
- full case body remains accessible;
- semantic visualization may be recomposed for mobile, never simply shrunk unreadably;
- critical explanatory text remains HTML where practical.

## 12. Design freedom
Claude Design IS allowed to choose:
- composition;
- hierarchy scale;
- whitespace;
- grid;
- editorial rhythm;
- card use where semantically useful;
- navigation presentation;
- typography application within approved Design System;
- responsive composition;
- treatment of Image Slots within their explicit function.

Claude Design is NOT allowed to choose:
- technology ontology;
- number/products;
- source meaning;
- case truth status;
- visual class substitution;
- whether required knowledge survives;
- public language exceptions;
- Hero identity;
- new claims.

## 13. Implementation feasibility envelope
Known target remains WordPress + Blocksy + Elementor Free.
No Elementor Pro, ACF, Loop Builder, premium carousel or new plugin is assumed.
This is a feasibility constraint, not a visual design language.
After approved Claude visual design, an implementation build sheet maps approved compositions to actual Blocksy/Elementor Free primitives.
If an approved composition cannot be implemented within stack, implementation adapts without losing semantic invariant; it does not silently simplify content.
