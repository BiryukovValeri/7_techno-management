## 0. Acceptance principle
A block is not PASS because it exists.
A block is PASS only when a visitor can recover the required understanding from the rendered result without relying on internal methodology knowledge.

For every contract below audit:
- REQUIRED KNOWLEDGE — what must survive;
- RELATIONSHIP — what must be understood about the entities;
- VISUAL CLASS — Hero / Technology Visualization / Image Slot / No Image;
- LOSS TEST — observable failure;
- FORBIDDEN TRANSFORMATION;
- RESPONSIVE SURVIVAL.

Defect classes:
CONTENT_LOSS / SEMANTIC_DRIFT / VISUAL_SUBSTITUTION / HERO_CLONING / LANGUAGE_VIOLATION / PRODUCT_ONTOLOGY_DRIFT / CASE_TRUNCATION / UNSUPPORTED_CLAIM / RESPONSIVE_SEMANTIC_LOSS.

### KT-H05 Decision quality

### KT-H06 Forms 17–23

### KT-H07 Evidence and cases

## 9. VISUAL TRANSFER TEST
Every visual object must declare one class:
HERO_IMAGE / TECHNOLOGY_VISUALIZATION / IMAGE_SLOT / DECORATIVE / NO_IMAGE.

Technology Visualization PASS requires:
- source identity;
- required nodes;
- required relations;
- required order where applicable;
- canonical terms;
- allowed visual changes;
- forbidden semantic changes;
- source-vs-web semantic diff.

Image Slot PASS requires:
- explicit comprehension function;
- subject tied to block;
- no evidence claim;
- no automatic Hero metaphor cloning.
If function cannot be stated in one concrete sentence → NO_IMAGE.

Using a new visual in place of a source Technology Visualization without approval = VISUAL_SUBSTITUTION.

## 10. RESPONSIVE TRANSFER TEST
At desktop/tablet/mobile verify:
- all required entities survive;
- relation survives;
- sequence survives;
- full case body remains reachable;
- visualization labels/relations remain readable;
- no essential information becomes hover-only;
- four products remain peer formats;
- navigation destinations remain reachable.
Failure = RESPONSIVE_SEMANTIC_LOSS.
