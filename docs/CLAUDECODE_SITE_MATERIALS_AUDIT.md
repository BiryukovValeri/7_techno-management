# `claudecode` Website-Materials Audit

Audit target: `BiryukovValeri/claudecode`, branch `codex/site-factory`.

## Inventory result

`70 Site` contains 273 non-junk files:

- 71 files are byte-identical to files in the seven Mac technology corpora;
- 202 files exist only in the repository-side site-production corpus;
- 23 duplicate SHA groups exist inside `70 Site`, largely because historical, transfer, and current packages preserve independent copies.

This means the Mac corpus and `claudecode/70 Site` are complementary. Neither can be treated as a replacement for the other.

## Historical/reference boundary

The repository also contains earlier Source Locks, Site Factory V1 packages, CLM versions, transfer packages, design-system candidates, and multiple main-site semantic models. Under `AGENTS.md` and `PROJECT_STATE.md`, newer-looking timestamps or filenames do not make them governing authority.

In particular, `MASTER_C_Level_Insight_Site_Factory_v3.0.md` is historical/reference where it conflicts with the approved protocol.

## Consistency warning

`PROJECT_STATE.md` names the current stage as `SITE FACTORY V1`, while a DA V2 instance and V2.1 Stage 01 amendment are also present. This audit does not choose between those execution routes. A direct current task or controller decision must identify which route governs before further site production.

## Transfer decision

`claudecode/70 Site` was not copied wholesale into this source repository. Doing so would mix current control files, active execution state, historical packages, and superseded material into one undifferentiated authority layer.

Instead:

- this repository holds the verified seven-technology Mac source corpus;
- `claudecode` remains the site-production control and execution repository;
- this audit provides the navigation bridge between them.
